# Persian Smart Batch Augmentation

افزایش داده (Data Augmentation) برای متن‌های فارسی با استفاده از مدل‌های زبانی محلی در **Ollama**، همراه با **بچ‌بندی هوشمند** و **پردازش موازی**.

این پروژه برای دیتاست‌های تحلیل احساسات (مثل نظرات دیجی‌کالا) نوشته شده است. هر متن را به مدل می‌دهد و یک بازنویسی جدید با همان مفهوم و لحن، اما با کلمات و ساختار متفاوت می‌گیرد؛ در نتیجه تعداد نمونه‌های آموزشی بدون جمع‌آوری داده‌ی جدید بیشتر می‌شود.

---

## ویژگی‌ها

- **بچ‌بندی هوشمند:** متن‌ها بر اساس طول مرتب می‌شوند تا متن‌های هم‌اندازه در یک بچ قرار بگیرند.
- **محدودیت دوگانه برای هر بچ:** هم تعداد متن (`max_batch_size`) و هم تعداد تقریبی توکن (`max_total_tokens`) کنترل می‌شود.
- **پردازش موازی:** چند بچ هم‌زمان با `ThreadPoolExecutor` به Ollama ارسال می‌شوند.
- **حفظ برچسب‌ها:** ستون‌های `Score` و `Suggestion` برای متن تولیدشده همان مقدار متن اصلی را دارند.
- **پرامپت آگاه از برچسب:** برچسب احساس (مثبت / منفی / خنثی) داخل پرامپت به مدل داده می‌شود تا لحن حفظ شود.
- **پاک‌سازی خروجی مدل:** شماره‌گذاری حذف می‌شود و فقط خطوط حاوی متن فارسی نگه داشته می‌شوند.
- **جایگزین امن:** اگر مدل کمتر از تعداد انتظار خروجی بدهد، برای متن‌های باقی‌مانده خود متن اصلی برگردانده می‌شود.

## نحوه‌ی کار

```
DataFrame
   │
   ▼
create_smart_batches()      مرتب‌سازی بر اساس طول + ساخت بچ‌ها
   │
   ▼
ThreadPoolExecutor          اجرای هم‌زمان چند بچ
   │
   ├── create_batch_prompt()     ساخت پرامپت فارسی برای بچ
   ├── POST به Ollama            ارسال به /api/generate
   └── parse_batch_response()    استخراج متن‌های جدید از پاسخ
   │
   ▼
DataFrame augmentation‌شده (Text, Score, Suggestion)
```

برآورد توکن‌ها به‌صورت تقریبی انجام می‌شود:

```
estimated_tokens = len(text) / 1.3 + 100
```

عدد `100` سربار پرامپت است.

## قالب دیتاست ورودی

فایل CSV باید این سه ستون را داشته باشد:

| ستون | توضیح |
|------|-------|
| `Text` | متن فارسی |
| `Score` | امتیاز اصلی نمونه |
| `Suggestion` | برچسب احساس: `1` مثبت، `2` خنثی، `3` منفی |


## نحوه‌ی استفاده

۱. فایل دیتاست را با نام `digikala_sentiment.csv` کنار نوت‌بوک قرار دهید (یا مسیر را در نوت‌بوک تغییر دهید).

۲. نوت‌بوک را باز کنید:

```bash
jupyter notebook persian_smart_batch_augmentation.ipynb
```

۳. سلول را اجرا کنید. در انتهای نوت‌بوک این کد اجرا می‌شود:

```python
augmenter = OllamaAugmenter(model="gemma3:12b")

df = pd.read_csv('digikala_sentiment.csv')

augmented_df = augmenter.augment_parallel_batches(df)
```

۴. برای ذخیره‌ی خروجی:

```python
augmented_df.to_csv('augmented.csv', index=False, encoding='utf-8-sig')
```

## تنظیمات

پارامترها در متد `__init__` کلاس `OllamaAugmenter` تعریف شده‌اند:

| پارامتر | پیش‌فرض | توضیح |
|---------|---------|-------|
| `model` | `gemma3:12b` | نام مدل در Ollama |
| `ollama_url` | `http://localhost:11434/api/generate` | آدرس API |
| `max_batch_size` | `6` | حداکثر تعداد متن در هر بچ |
| `max_concurrent_batches` | `4` | حداکثر تعداد بچ هم‌زمان |
| `max_total_tokens` | `1500` | سقف توکن تخمینی هر بچ |

تنظیمات تولید (در `process_single_batch`): `temperature = 0.7` و `num_predict = 1000`.

## نکات مهم

- **موازی‌سازی واقعی در Ollama:** اگر سرور Ollama هم‌زمانی را محدود کرده باشد، درخواست‌ها صف می‌شوند. برای استفاده‌ی کامل می‌توانید متغیر محیطی `OLLAMA_NUM_PARALLEL` را متناسب با `max_concurrent_batches` تنظیم کنید و حافظه‌ی GPU/RAM را در نظر بگیرید.
- **ترتیب خروجی:** چون متن‌ها بر اساس طول مرتب می‌شوند و بچ‌ها به‌صورت موازی تمام می‌شوند، ترتیب سطرهای خروجی با ورودی یکسان نیست.
- **بچ‌های ناموفق:** اگر درخواست یک بچ با خطا یا timeout مواجه شود، آن بچ در خروجی نمی‌آید و فقط پیام خطا چاپ می‌شود.
- **نیاز به بازبینی:** کیفیت بازنویسی‌ها به مدل بستگی دارد. پیش از آموزش، نمونه‌ای از خروجی را بررسی کنید.
- **زمان‌بندی:** timeout هر درخواست ۱۲۰۰ ثانیه است و مدل‌های بزرگ‌تر ممکن است زمان بیشتری بخواهند.
